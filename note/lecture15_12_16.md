# 链路层
第二层 使用frame(帧)封装数据

不同链路层协议在不同链路上传输数据报 wifi ehternet等都在不同链路

成帧 (Framing)，链路接入 (link access):将数据报封装成帧，加上帧头、帧尾部
如果数据报和关键字重复怎么处理？转义
如果采用的是共享介质，信道接入获得信道访问权；在帧头部使用“MAC”地址来标示源和目的

MAC media acccess control，并不是因特网独有的

相邻节点间可靠交付(Reliable Delivery)：对于光纤，不需要，靠传输层去纠正即可；
wifi需要，不然从us传输到cn，最后一跳的wifi丢包之后重传是不合理的

**链路层的服务**
流控: 调节相邻发送和接收节点之间的速度
差错检测: 由信号衰减、噪声引起的差错，接收端检测错误、发出重传信号或丢帧 
差错纠正: 接收端识别并纠正比特错误而不重传
半双工和全双工:对于半双工，链路两端的节点可以传输，但不能同时传输

**链路层的实现**
在每一个主机、路由器、交换机每一个端口上通过网卡(network interface card, NIC)实现，连接到主机总线

**发送端**
在帧中封装数据报，增加差错控制编码，可靠的数据传输，流量控制等

**接收端**
检查有无出错，解封装数据报，将其交给上层
**这并不是端到端的两端，而是链路上的两端，是连接两跳的！**

## 检错纠错
EDC: 差错检测和纠正比特 Error Detection and Correction bits 

**奇偶校验（Parity checking ）**
设置奇偶校验位，从而有偶数/奇数个1
二维奇偶校验:检测和纠正单比特错误

**Internet 校验和**
可以检测传输段中的错误

发送方:
将UDP段的内容(包括UDP头部字段和IP地址)视为16位整数序列
计算校验和: 分段内容的相加（得到的和的反码）
校验和放进UDP校验和字段

接收方:
计算接收的段的校验和，检查计算的校验和是否等于校验和字段值

**循环冗余检测 Cyclic Redundancy Check (CRC)** 可以检测所有小于r+1位突发错误
更强大的差错检测码
D: 数据比特(假设这些是二进制数)
G: 比特模式 (生成多项式), r+1 比特

发送方: 计算r位CRC比特R, 使D拼接上R得到的(D,R)，即$D*2^r  xor R$正好被G整除 (模2运算)
接收方知道G，将(D,R)除以G，余数非零则检测到错误

## 多路访问协议
链路有两种:
1. 点对点以太网交换机、主机之间
2. 广播 (共享线路或媒体)，传统以太网、4G/5G..

广播是共享链路的，两个或多个节点同时传输就会产生冲突，因此需要协议确定节点如何共享信道
而且，关于信道共享的通信必须使用信道本身，没有用于协调的带外(out of band)信道

对于速率为R bps的多路访问信道 (multiple access channel, 也叫MAC)
我们希望当一个节点想要发送时，它可以以速率R bps发送；
当M个节点需要发送时，每个节点可以以平均速率R/M bps发送；
而且算法完全去中心化

**三大类:**
1. 信道划分协议
将信道分成更小的片段(时隙、频率、编码)
分配片段给节点独占使用

2. 随机接入协议
不划分信道，允许冲突
能从冲突中恢复

3. “轮流”协议	
通过轮流访问信道避免冲突，即轮询

**信道划分MAC协议: TDMA**
TDMA: time division multiple access 时分复用
轮流访问信道，每个站点在每轮中获得固定长度的时隙(长度=分组传输时间)
未使用的时隙变为空闲

**信道划分MAC协议：FDMA**
FDMA: frequency division multiple access 频分复用
信道的有效频率范围被分成一个个小的频段
每个站点被分配一个固定的频段

**信道划分MAC协议：CDMA**
CDMA: code division multiple access 码分复用
所有站点在整个频段上同时进行传输, 每个节点分配一种不同的编码
完全无冲突，抗干扰性强，广泛应用于蜂窝电话中

TDMA:不同的人在不同的时刻讲话
FDMA:不同的组在不同的小房间里通信
CDMA:不同的人使用不同的语言讲话

**随机接入协议**
规定冲突检测与恢复的方法

经典例子：
**时隙 ALOHA**
时间分成大小相等的时隙，即传输1帧的时间（假设帧等长），且节点只在时隙开始时传输
并且是时钟同步的，那么：
当节点获得新帧时，在下一个时隙发送
如果没有冲突: 节点能够在下一时隙发送新帧
如果有冲突: 节点在随后每一个时隙以概率p重传帧，直到成功

优点:
单个活跃节点可以以信道的全速率连续传输
高度去中心化：仅需要节点之间在时隙上的同步，而且实现很简单

缺点：
冲突时浪费时隙，而且要时钟同步
节点检测冲突的时间可能小于帧传输的时间

那么如果节点N为无穷大时，p取到合适的值，极限为  1/e=0.37
即信道利用率37%

**纯 ALOHA**
无时隙 ALOHA:，无需节点间时间同步，更简单
当帧第一次到达时立即传输
冲突时，因为没有时钟，一个帧可能和上一个与下一个都产生冲突 
则经过计算，可得选择最佳的p，N无穷大时信道利用率1/2e，即18.4%

**CSMA(载波侦听多路访问)**
CSMA: carrier sense multiple access
在传输前先侦听信道，如果侦听到信道空闲，传送整个帧
如果侦听到信道忙，推迟传送
类似于人类对话

然而，因为传播延迟，冲突仍然可能发生，因此其冲突检测为：
**CSMA/CD (collision detection 冲突检测)**
有线局域网中容易实现：检测信号强度，比较传输与接收到的信号是否相同
在无线局域网中实现困难：自身信号远大于其他节点信号

在以太网中，CSMA/CD实现为：

1. 适配器（网卡）从网络层获得数据报，创建帧
2. 适配器发送前侦听信道，如果闲，开始传送帧；如果忙，等到闲
3. 发送过程中一遍发送一遍进行冲突检测，如果检测到冲突则放弃,之后尝试重发
4. 发送方适配器检测到冲突，除放弃发送外，还发送Jam信号以便所有站点都知道冲突
5. 放弃传输后，适配器进入指数退避状态，随机roll一个m，等待2^m*512 bit传输时间后后进入状态2；经历的冲突越多，随机数选择的上界越大（binary exponential backoff 二进制指数退避算法）


但是，有时冲突检测不出来，有传输延迟
因此，我们让包大一点，以至于可以覆盖延迟的范围即可

**当帧的传输时间接近1或者无穷大时，传输效率接近1**
$efficiency = \frac{1}{1 + 5 * \frac{t_{prop}}{t_{trans}}}$

**“轮流”MAC 协议**
信道划分协议在低负载时效率低，随机接入协议的冲突开销大

对于轮流协议

第一种：通过Polling 轮询，中央控制器依次邀请其他节点进行传输
它对设备的要求很低，让它传，它就传
缺点在于轮询开销、延迟与单点故障(主节点，控制器出错则有问题)
蓝牙就是使用轮询

第二种：令牌传递 token passing，control token的报文按顺序从一个节点传递到下一个节点，持有令牌时传输
缺点在于令牌开销、延迟与单点故障(如果令牌故障，例如出现两个就有问题)

在电缆接入网络中，有多个下行FDM频分复用，多个上行信道，用TDM时分复用
由DOCSIS: data over cable service interface specification定义

## 局域网
寻址，ARP协议

48位 MAC 地址，是链路层的地址（ip是网络层的地址）
接口的地址，用于网络层转发
一般是在制造时就固定在网卡中的，当然也有软件可以修改

LAN中的每个接口，都有唯一的48位MAC地址，也有一个本地唯一的32位IP地址
交换机没有ip地址，它也 **没有** MAC地址！

MAC地址分配由IEEE管理
制造商购买部分MAC地址空间（以确保唯一性）

IP地址不可移动，依赖于节点所连接的IP子网，但是MAC是固定的
而且，MAC只能看出制造商，其他信息都看不出来，都是随机的
而ip是能看出地理位置等等的

**ARP: address resolution protocol 地址解析协议**
LAN中每个IP节点(主机, 路由器) 都有ARP表，保存部分结点的的IP/MAC地址映射，且有TTL记录时间，例如20min

发送一个包后，设备先查看数据帧中的表头，包括Src MAC和Dst MAC
如果找到则转发
如果没有找到，则广播ARP请求, 包含目的地的IP地址Dst MAC = FF-FF-FF-FF-FF-FF，
则LAN上所有节点都会收到ARP请求

Dst用ARP响应回复（这次不是广播，是单播），给出它的MAC地址

路由到另一个子网，就需要寻址
Src会把MAC地址设置为第一跳的路由器；第一跳的路由器会拆掉链路层报头，传到IP层，通过ARP协议，路由器会把链路层报头换成新的MAC地址并传递下去

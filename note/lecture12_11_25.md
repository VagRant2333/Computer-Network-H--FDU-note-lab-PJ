## 路由协议
即寻路算法，使得跳数（成本）/时间/拥塞最少

链路的代价：经常定义跳数为代价（即总是为1），或者与带宽成反比，或者与拥塞成反比

算法分为几种：
1.全局 所有的路由器拥有完整的拓扑和边的代价的信息 “link state” 算法
2.分布式 只知道邻居链路代价，需要迭代 “distance vector” 算法
3.静态 路由随时间变化慢（比如数据中心）
4.动态 定期更新以相应链路代价的变化

### link-state路由算法
**Dijkstra link-state 路由算法**
集中的: 网络拓扑结构、链路代价为所有节点所知
通过“link state broadcast” 完成，所有节点都有相同的信息
计算从一个节点(“源”)到所有其他节点的最小代价路径，给出该节点的转发表
经过k次迭代，知道到k个目的地的代价最小的路径

```
Initialization: 
  N' = {u}                               /* 最小代价路径明确的结点集合 */
   for all nodes v 
     if v adjacent to u            /* u initially knows direct-path-cost only to  direct neighbors    */
         then D(v) = Cu,v                   /* Dv为从源到v到预估最小代价，Cu,v为链路代价 */
     else D(v) = ∞ 

Loop:
    find w not in N' such that D(w) is a minimum 
    add w to N' 
    update D(v) for all v adjacent to w and not in N' : 
        D(v) = min ( D(v),  D(w) + Cw,v) 
until all nodes in N'
```

notes:
通过跟踪前导节点构造最小代价路径树
可能存在多条最小代价路径，可根据目标选择，如负载均衡
**讨论**
在我们得到每一个最短路之后，怎么生成转发表？每个结点转发到最小代价路径树的下一结点
甚至还可以路由表中一个目的地对应两个端口号，为了防止后发先至（会导致dupACK而降速），因此通过包头中的五元组去做哈希来选择路径，使得同一个tcp流进同一个端口 **ECMP** equal cost multi port

Dijkstra一共n(n+1)/2次比较，O(n^2)，因此需要优化：大多数结点预估距离不变，所以只需要在上次的结点排序上优化，可以实现O(nlogn)

此外还要考虑消息复杂度，每台路由器要向n台其他路由器广播自己，因此需要O(n)个链路来传播，一共O(n^2)

而且Dijkstra还有路由震荡问题：
当链路代价取决于链路承担的流量时，给定了一个新代价去计算新的路由，这会改变链路上的流量，可能又使得链路的代价变化，需要重新计算路由...
路径无法收敛，使得乱序 loop 计算开销大等等问题出现

怎么解决：一跳的cost就是1，和流量等无关（当然这也会使得最短路无法自适应）

### distance-vector距离向量算法

基于BF等式动态规划，$D_x(y) = min_v (C_{x,v} + D_v(y) )$
v为x的邻居，D_x(y)为最少x到y代价路径

假设u的邻居节点, x,v,w, 已知它们到z的最小代价路径，取最小值的节点x是u到达目的地z的预估最小代价路径上的下一跳

核心想法: 
每个节点定时地或Distance Vector(DV)有变化时将自己的DV估计值发送给相邻节点；
当x从任何邻居收到DV时，采用BF等式重新计算并更新它自己的DV；
在正常情况下, Dx(y)估计值最终收敛于实际的最小代价值

即，对于每个结点，都等待本地链路代价变化或者邻居更新D(v)；之后计算自己的新D(v)，如果有更新则通知邻居

因此，最坏情况网络直径为n且网络为链且从一端开始传播，则需要n次迭代
**链路代价变化：**
好消息传得快 坏消息传得慢（无穷计数问题）
因为，如果Dv变小（代价减小），向外传播之后不太需要传播回来，网络会很快收敛到最优

然而如果Dv变大，例如Dv从4变成60
y检测到到x的直接链路的新代价是60，但z说它有一条路径的成本是5。y计算出，通过z, 到x的新代价是6; 通知z其到x新路径的代价为6; z会进一步修改通知y到x的代价为7...一直循环到60

甚至，如果代价变成无穷，则永远不收敛

**解决方案**
可采用限制最大跳数（16 跳不可达）、触发更新（故障时立即发更新报文，而非等周期）、水平分割（避免路由信息反向回传）等措施。
当然这个问题是算法固有，无法彻底解决

### LS DV算法比较
link-state是要把信息发给所有人，但是每个信息比较小；O(n^2)
distance-vector需要把n维的vector发给自己的邻居，信息大但是接收者少，收敛时间会变化

递归收敛会更慢甚至可能无穷计数，中间状态也可能有环路

健壮性：如果路由器发生故障或被破坏，会发生什么?
LS: 
路由器会通告不正确的链路代价；因为每个路由器只计算自己的路由表所以错误信息影响较小，局部
DV:
路由器可能通告全网所有路由器不正确的路径代价，可能产生黑洞（一个路由器发出了错误的，我到某个点的代价为0时）
每个路由器的DV可以被其他路由器使用: 错误可以扩散到整个网络

## ISP内路由 OSPF
OSPF是路由协议，使用的算法就是link-state

实际上，因特网: a network of networks
所以我们需要将路由器聚合到称为“autonomous systems” (AS, 自治系统)的区域中 (亦称“domains”)

对于同一AS内路由器之间的路由intra-AS (亦称 “intra-domain”)：
AS内所有路由器必须运行相同的域内协议
不同自治系统中的路由器可以运行不同的域内路由协议

借助网关路由器(Gateway 在AS的边缘，通过链路连接到其它AS的路由器)实现inter-AS (亦称 “inter-domain”,AS之间的路由)

AS内部，转发表由AS内路由算法和AS间路由算法所配置，AS内路由决定AS内目的地的表项；AS间和AS内路由确定外部目的地的表项

而AS1域间路由 还需要了解哪些目的地可以通过AS2到达，哪些可以通过AS3到达，将此可达性信息传播到AS1中的所有路由器

在AS内的路由常用OSPF Open Shortest Path First(RI太老 EIGRP之前是专利)

### ECN explicit congestion notification
即：由网络路由器标记IP首部ToS字段中的两个比特；之后在接收方返回的ACK中附上这个信息
比如10 1表示当前是支持ECN的（只要有一跳不支持ECN，则忽略） 0表示目前没有拥塞

回来的信号是传输层的ACK 而去的信号是IP层(网络层，更底层)

### TCP公平性
希望K个TCP会话共享同一带宽为R的瓶颈链路时，各个会话的平均速率为R/K

对于TCP newReno，它可以支持公平性，因为它是 **AIMD** 即 **加性增，乘性减（慢启动每次加一，遇到丢包会除二）**
那么第一个流先出现，占用率100% 之后第二个流出现，它也会慢慢增加带宽，直到出现丢包
这个丢包是buffer满了，所以两个流都会丢包，于是两个都除以2了：第一个流占用率高，于是除以2下降的更多
而加cwnd时，大家是一起加1，增加比例相同。因此一段时间后二者带宽占用接近

当然了，也不一定一直满足公平性：实际上我们假设了两个流RTT相同，而且拥塞避免时流的数量固定

如果流的数量不停的在变，还没有收敛到稳定公平时这个流就结束了；但这个问题不大，实际上RTT不同会导致的不公平更严重，但是无法解决

公平性实际上是不绝对的。有很多流媒体常使用UDP，它无法接受TCP的流量管控，完全由应用层实现；那么TCP自己降速，UDP依然我行我素

再说，两个主机之间传输，如果开多个并行连接，一个应用占用多个流，也可以偷到带宽

## 传输层的功能演变
历史上TCP有不同的发展，比如早期的增加in-flight数量/流水线深度
比如无线网络出现之后，无线链路的丢包，将其视为拥塞丢包
比如长延迟链路，RTT非常长；比如数据中心对延迟非常敏感；比如背景流，是低优先级的背景TCP流量（别人一用就让出带宽）

在UDP基础上将传输层功能移动到应用层，出现了 **HTTP/3:QUIC**

### QUIC: Quick UDP Internet Connections
**应用层协议** 以UDP为基础提高HTTP性能，谷歌提出
HTTP/2是并行分片，下面还有TLS(transmit layer security)的加密层，再下面是TCP和IP
HTTP/3将HTTP/2简化（去掉很多复用、公平性保证等等），下面是Quic 再下面是UDP和IP

QUIC同样采用错误和拥塞控制，此外优化连接建立阶段，在一个RTT内建立通信、实现拥塞控制、身份验证、加密
而且在单个QUIC连接上会多路复用多个应用级的流，它们是 **共同的拥塞控制**

TCP握手1个RTT，TLS的身份认证和加密状态也需要1个RTT 而QUIC总共只需要一个RTT
同时，TCP是串行请求文件的，而QUIC是流，并行，共享一个拥塞控制 没有HOL:队头阻塞

# 第四章 网络层：网络平面
*网络服务模型，通过路由进行转发：路由器原理（寻址 泛化转发...） IP协议 NAT & MiddleBox*

**网络层服务和协议：** *传输层协议只在两端的主机上运行*
在发送方和接收方之间传输报文段
发送方： 封装**报文段到数据报**中, 递交给链路层
接收方： 递交报文段到传输层
网络层协议存在于每个主机和路由器
**路由器:**
检查每一个经过它的IP数据报的头部
将数据报从输入端口移交到输出端口，从而实现将数据包在端到端的路径上传输的目的（当然，它会进行处理，比如校验和，比如TTL-1，当然还有查转发表） 
*为什么要TTL？担心网络有死循环，几个包一直在里面转，吃带宽；因此TTL常128，网络几乎不会超过几十跳*

（传统的）交换机不支持网络层，只支持更下面的链路层、物理层

#### 网络层的功能
1. 转发，把分组从路由器的输入链路移动到合适的输出链路
2. 路由：决定分组从源点到终点路经（路由算法。不同于寻路算法，并没有一个集中的地图能让你看到所有信息）

#### 网络层
1. 数据平面：本地，是每个路由器的功能；查找转发表就是在数据平面的 决定数据报该如何转发到输出端口（不智能，要求快）
2. 控制平面：网络范围的逻辑（比如维护转发表），决定数据报如何在源主机到目的主机的路径上的路由器之间进行路由
   控制平面的方法：传统路由算法 / 软件定义网络(software defined networking SDN) 在远程服务器实现的中心化控制器

**传统路由器中，** 每个路由器都有单独的路由控制算法组件，在控制平面进行交互，最后各自计算出转发表(forwarding table)
控制平面之下的，就是数据平面，它查询转发表并转发数据（如果发现自己的IP就是接收方，就把数据传给控制平面）
转发表，就是两个平面的接口

问题是，传统路由器的去中心化有着去中心化的所有问题

**SDN的控制平面：** 每个路由器不用再有复杂的控制平面和算法，只需要一个Controller Agents(CAs 本地控制代理)
CAs和远程的控制器交互。远程控制器会计算出控制信号给路由器 **中心化**

**网络层可以实现的服务：**
取保交付 延迟保证、有序交付、对分组间隔变化的控制

但是，这些服务，传输层都可以做到！所以，最后网络层采用的 **服务模型是 Best Effort：** 尽力而为，没有任何Quality of Service(QoS)保证。这样，路由器变得简单，网络核心变得非常快。至于这些带宽保证、丢包检查...由网络边缘的主机在更上层去慢慢完成
*当年出现过ATM等架构和CBR ABR Intserv Guaranteed等服务模型能保证QoS，但是现在逐渐弃用*
*实际上，机制简单就是好，带宽供应充足就够了*

#### 路由器结构
1. 线卡 交换卡等 在硬件层面实现纳秒级数据平面转发（查询转发表）
2. 控制卡（cpu），在软件层面实现毫秒级控制平面管理（维护路由表）
3. 路由表vs转发表：从路由表镜像得到转发表；当然，路由表和转发表除了更新的一点点时间不同外一直相同，所以我们一般认为二者等价

接收物理层信号（当然，要等所有包到齐再处理），传到链路层，再传到网络层（IP层），之后进入路由器的数据平面，包头校验、ttl-1、forwarding都在纳秒级别进行。这个细粒度，软件是做不到的（控制平面的cpu上的频率都是毫秒级），所以数据平面是使用硬件实现

**输入端口功能**
物理层：接收bit级数据；链路层：chpt6详细介绍
之后，分布式交换：传统路由器使用头部字段的值在转发表中查到输出端口，是基于目的地的转发（SDN是泛化转发，基于头部字段的任意集合进行转发）
数据报的到达速度超过交换结构的转发速度时，输入端口会排队

**转发表**
实际上，转发表不是维护一个具体IP，而是维护网段
**涉及到最长前缀匹配算法**
| Destination Address Range | Link Interface |
|-|-|
| 1100100 0010111 0001000\*** through 1100100 0010111 0001111\*** | 0 |
| 1100100 0010111 0001001\*** 1100100 0010111 0010111 0001111\*** | 3 |
| default | 2 |
*在这里是通配符
如果一不小心，范围没有划分的很规整以至于地址之间有重叠，那么就没有办法直接用通配符解决，那么常选择更小的网段（它更精细，更准确）

RAM是地址寻址，CAM是content寻址，可以实现并行比较，输出匹配的表对应的Link interface；
CAM可以和RAM连用，实现类似哈希表的功能（也就是，我们要用硬件实现哈希）
content -> |CAM| -> addr -> |RAM| -> 差找到的内容

还可以TCAM(ternary content addressable memories)T指三进制，使用通配符 TCAM可以在一个周期内完成检索
一般而言，存储是最上面的前缀越短（即通配符越多）
所以，TCAM会逐一比较，之后进过一个优先级解析得到匹配上的前缀最长的地址

#### 交换结构
**交换速率:** 分组从输入端口到输出端口传输的速率
通常以 输入/输出 线速率的倍数作为单位衡量（输入为线速率）
N个输入端口: 交换速率是线速率的N倍是一个较为理想的情况（因为最差情况，N个输入端口都要转发到同一个输出端口，需要很快才不会拥堵）
**物理实现:** 
1. memory 共享内存。在最差情况下它需要的带宽为$2 \lambda N$ lambda为输入速率 乘以2是因为存/读都占带宽
   它的劣势是N lambda增加都对带宽（内存的system bus）要求增加；而且目前memory带宽的发展并不快
   因此，一般只有低端路由器使用
2. bus（总线 PCI PCIE）它的瓶颈也在于带宽，$\lambda N$ 不用乘以2，因为它就是线，存/读同体
   memory带宽这时候和N无关，常用于中端路由器
3. interconnection-network，就是两两互联，可以并行把任意输入传到输出
   交换网络有多种，常见Crossbar结构和Clos网络
